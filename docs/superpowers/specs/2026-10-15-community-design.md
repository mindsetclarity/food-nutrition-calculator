# Community — Design

Date: 2026-10-15
Status: draft, awaiting owner approval (builder check done)

## Intent and the why

foodnutritioncalculator.com is a read-only tool today: visitors look up foods and calculate
meals, then leave. The owner wants a community at `/community` where:

1. **Members help each other** with diet, exercise and physique (progress/transformation) tips.
2. **Members talk directly to the owner** about the website — privately, and also in a public
   feedback topic where ideas can be discussed and upvoted.
3. **Membership pays off**: every member gets their own unique referral code for the owner's
   Bhaskar app. This is also the main business reason: the community feeds Bhaskar signups.

Success looks like: real members posting and replying, the owner hearing what to fix on the
site, and Bhaskar codes being handed out and redeemed.

## Goals

- Public community at `/community`, readable by anyone (good for Google), with four topics:
  **Diet**, **Exercise**, **Physique / Progress**, **Website feedback**.
- Sign up with **Google** or **email + password** (email verified, password reset by email).
- Members pick a **username**; real name and email are never shown publicly.
- Signed-in members can **post** (title, text, optional photos), **reply**, **upvote**, and
  **report** posts/replies.
- **Private "Message the owner"** form: only the owner sees it; owner replies from the admin
  page; the member sees the reply on their account page.
- Each member gets a **unique Bhaskar referral code**, generated by this website on signup and
  shown on their account page (and nowhere else).
- A **secure verification endpoint** the Bhaskar app calls to check a code is real.
- **Admin page** (owner only): delete posts/replies/photos, ban users, see reports, read and
  reply to private feedback.
- Posts go **live instantly** (except photos from accounts under 7 days old, which wait for approval); the owner removes bad content afterwards. Reported items are
  flagged for the owner.
- A short **"not medical advice"** disclaimer on every community page.

## Non-goals (for now)

- What the referral code is worth in Bhaskar (discount, free premium…) — owner hasn't decided;
  this site only generates, shows and verifies codes.
- Email notifications to the owner — owner checks the admin page instead.
- Direct messages between members, following, notifications, profiles with bios.
- Moderators other than the owner.
- Languages other than English.

## Anti-goals (would be a failure even if it works)

- Members' emails or real names leaking publicly.
- Spam or bot signups flooding the site and hurting its SEO/reputation.
- Harmful advice (extreme diets, eating disorders) or explicit photos staying up because the
  owner can't find and remove them fast.
- Referral codes that can be guessed, or listed by anyone calling the verify endpoint.
- Slowing down or breaking the existing calculator/food pages.

## Constraints

- Existing stack: Astro 7 with `output: 'server'` on Cloudflare Workers (`@astrojs/cloudflare`),
  Tailwind 4, `trailingSlash: 'never'`. A `SESSION` KV namespace already exists.
- Build on what's there: same `SiteLayout`, same design system (`DESIGN.md`), same URL style.
- Target audience is US/UK first (English, tier-1 tone).
- Owner email for admin access: mindsetclarityofficial@gmail.com.

### Consequences of these answers

- **Redeem contract with Bhaskar:** `POST /api/referral/redeem` `{ code }` → `{ ok: true }` the
  first time, `{ ok: false, reason: "used" | "invalid" | "revoked" }` after. Atomic in D1
  (single `UPDATE … WHERE redeemed_at IS NULL`). `POST /api/referral/verify` stays read-only.
  The member's account page shows "Redeemed on <date>" once used.
- **Free plan:** sessions live in **D1** (not KV — KV Free allows ~1,000 writes/day). Password
  hashing uses Web Crypto PBKDF2-SHA256 (native, runs outside JS); iteration count is set to the
  highest that stays within Free CPU limits, measured during build. If it can't, the fallback is
  Google-only sign-in for new signups, raised with the owner before shipping.
- **Legal pages:** `/privacy` and `/terms` get updated to cover user accounts, user content and
  photos, Google sign-in, Resend, R2 storage, the 18+ rule, and account deletion. Owner approves
  the wording before launch.

## Builder's calls (marked as mine, owner can override)

- **Storage:** Cloudflare **D1** for users/sessions/posts/replies/votes/reports/feedback/codes;
  **R2** for photos. All native to the current host.
- **Auth:** implemented in-house (Google OAuth via standard OAuth 2.0 code flow; passwords
  hashed with PBKDF2 from Web Crypto, which Workers supports natively). No auth SaaS.
- **Referral code format:** `BSK-` + 8 random characters from a no-lookalike alphabet
  (e.g. `BSK-7KQ4M9TX`), from `crypto.getRandomValues`, unique index in D1.
- **Verify/redeem endpoints:** `POST /api/referral/verify` and `/redeem` with a shared secret header
  (`Authorization: Bearer <BHASKAR_API_SECRET>`), body `{ code }`, returns
  `{ valid, memberSince }` — no emails or usernames. Rate limited. Owner gives the secret to
  the Bhaskar app.
- **Photos:** up to 4 per post, JPEG/PNG/WebP, max 5 MB each, resized/re-encoded client-side
  before upload, served from R2. Photo posts only allowed for accounts with a verified email or
  Google login.
- **Spam:** Cloudflare Turnstile on signup and on posting; per-user rate limits (e.g. 5 posts
  and 30 replies per hour); new accounts can't post links until their first day passes.
- **Ordering:** each topic lists newest first with a "Top" toggle (by upvotes).
- **Bans:** banned users can still read but not post/reply/vote; their content is hidden.
- **SEO:** post pages are indexable with canonical URLs `/community/<topic>/<id>-<slug>`;
  the public feedback topic is `noindex` (low value for search). Post pages added to sitemap.
- **Deletion:** members can delete their own posts/replies and their account (removes their
  content and photos; code stays recorded as revoked so Bhaskar stops accepting it).
- **Pages:** `/community`, `/community/<topic>`, `/community/<topic>/<id>-<slug>`,
  `/community/new`, `/account` (username, referral code, private feedback + owner replies),
  `/login`, `/signup`, `/admin`.
