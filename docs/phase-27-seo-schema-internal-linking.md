# Phase 27: SEO, Schema, Sitemap, Robots & Internal Linking Pass

## 1. Purpose of Phase 27
Make Food Nutrition Calculator technically SEO-ready and internally well-linked while preserving safety, accuracy, performance, accessibility, and trust. Focus was placed on providing proper titles, descriptions, canonical URLs, structured JSON-LD schemas, breadcrumbs, sitemaps, and robots.txt. 

## 2. SEO helpers/components created
- **`src/lib/seo/siteConfig.ts`**: Contains base URL, site name, and default meta tags.
- **`src/lib/seo/types.ts`**: Strict TypeScript interfaces for SEO metadata to ensure standardization.
- **`src/lib/seo/metadata.ts`**: Helper functions that generate deterministic `og:title`, canonical URLs, and twitter cards.
- **`src/lib/seo/schema.ts`**: JSON-LD schema factories containing safe, valid configurations (e.g., `WebSite`, `WebPage`, `Article`, `FAQPage`, `SoftwareApplication`, and `BreadcrumbList`).
- **`src/components/seo/SeoHead.astro`**: Centralized component injected into the `<head>` of all layouts to render titles, metas, and schemas cleanly.
- **`src/components/seo/JsonLd.astro`**: Component to safely `JSON.stringify` schema data into `<script type="application/ld+json">`.
- **`src/components/seo/Breadcrumbs.astro`**: Clean semantic ordered list for breadcrumbs, complete with automatic JSON-LD markup.

## 3. Metadata strategy
- Updated `Layout.astro` and `SiteLayout.astro` to consume `SeoHead.astro`.
- Integrated strict `title` and `description` props customized per page. 
- Descriptions are 120-160 chars and avoid keyword stuffing.

## 4. Canonical URL strategy
- Canonical URLs are automatically derived from `Astro.url.pathname` and prefixed with the production domain `https://foodnutritioncalculator.com`.
- Trailing slashes are stripped predictably.

## 5. Open Graph/Twitter strategy
- Integrated `og:title`, `og:description`, `og:url`, `og:type`, `og:site_name`, and `og:locale`.
- Integrated `twitter:card="summary_large_image"` globally.
- Avoided fake images. Only real images will be used if `ogImage` is passed.

## 6. JSON-LD schema strategy
- Injected using the centralized `JsonLd.astro` component to keep the DOM clean.
- Only injected on pages where accurate data is known (e.g., Tools get `SoftwareApplication`, Articles get `Article` + `FAQPage`, etc.).

## 7. Schema types used and why
- **`WebSite`**: Broad homepage definition.
- **`Organization`**: Maps the site owner without inventing details.
- **`WebPage`**: Used for standard views like `/foods` or `/learn`.
- **`BreadcrumbList`**: Automatically generated by `Breadcrumbs.astro` to help search engines understand structure.
- **`SoftwareApplication`**: Used for `/calculator`, `/recipe-nutrition-calculator`, `/compare-foods`, and `/meal-calorie-calculator` to establish the page as an interactive tool rather than just text.
- **`Article`** and **`FAQPage`**: Used for `/learn/[slug]` where there is heavy reading material and explicit Q&A lists.

## 8. Schema intentionally skipped and why
- **`NutritionInformation`**: Skipped injecting into `/foods/[slug]` to avoid claiming absolute medical truth over variable data. WebPage is sufficient.
- **`Review`/`AggregateRating`**: Skipped because there are no real user reviews. 

## 9. Sitemap strategy
- Created `src/pages/sitemap.xml.ts` as a native Astro API endpoint.
- Iterates over all known static routes, `getAllFoodPages()`, and `getAllLearnArticles()`.
- Correctly generates valid XML. Does not include `/api/` endpoints.

## 10. Robots.txt strategy
- Created `src/pages/robots.txt.ts`.
- Allows `*` user-agents.
- Disallows `/api/`.
- Links to the absolute URL of the sitemap.

## 11. Internal linking strategy
- The homepage and header components already contain clean internal links to all major tools (`/calculator`, `/recipe-nutrition-calculator`, `/compare-foods`, `/meal-calorie-calculator`, `/foods`, `/learn`).
- Added robust breadcrumb trails across Food Details, Learn Articles, and Trust pages.

## 12. Dynamic foods page SEO strategy
- Mapped SEO fields to `/foods/[slug]` dynamically based on the dataset entry. Added breadcrumbs back to the foods directory.

## 13. Learn article SEO strategy
- Rendered dynamic TOCs, Breadcrumbs, and injected `Article` schema along with conditionally rendering `FAQPage` schema.

## 14. Trust/legal page SEO strategy
- Automatically wraps all content in `TrustPageShell` with breadcrumbs and `WebPage` schema based on the `eyebrow` prop.

## 15. Content safety rules
- No guarantees of medical accuracy were added.
- Existing disclaimers inside metadata boundaries were preserved.

## 16. Accessibility/performance preservation
- The `Breadcrumbs.astro` component uses `aria-label="Breadcrumb"` and `aria-current="page"`.
- Metadata rendering happens entirely on the server via Astro, adding virtually 0 overhead to the client.

## 17. What was intentionally not implemented
- Paid SEO plugins, analytics scripts, and cookie banners.
- SearchAction schema in WebSite (skipped due to potential ambiguity with our internal API routing vs traditional SSR search strings).

## 18. Known limitations
- The sitemap endpoint dynamically pulls from the local DB. It is fast enough right now, but for >10,000 routes in the future, it would be better served by a physical build-time `sitemap.xml` generated via integration.
